# Hiresync 취업정보 사이트 설계 문서 (Spec)

**날짜**: 2026-06-11  
**상태**: Draft (User Review Required)  
**작성자**: Gemini CLI

## 1. 개요 (Overview)
Hiresync는 구직자가 웹브라우저를 통해 현재 진행 중인 채용 정보를 빠르고 효율적으로 확인할 수 있는 플랫폼입니다. 관리자는 PDF 업로드, URL 등록, 이메일 수신 등 다양한 경로로 채용 정보를 시스템에 입력하며, AI가 추출한 정보를 최종 검토 및 승인하여 신뢰도 높은 데이터를 제공합니다.

## 2. 핵심 개발 원칙 (Core Principles)
1.  **한국어 중심 소통**: 모든 문서(PRD, Spec, Plan 등), 코드 주석 및 소통은 한국어로 진행합니다.
2.  **코드 영문 관례**: 소스 코드(명명 규칙 등)는 영문 관례를 엄격히 준수합니다.
3.  **테스트 중심 개발 (TDD)**: 모든 기능 구현 시 반드시 테스트 코드를 포함합니다.
4.  **보안 최우선**: 개인정보 및 민감 데이터 처리에 있어 보안을 최우선으로 고려합니다.

## 3. 요구사항 (Requirements)

### 3.1 기능적 요구사항 (Functional)
*   **구직자**:
    *   채용 공고 목록 조회 (회사명, 위치, 분야, 조건, 기간, 방법, 급여 등).
    *   사람인/잡코리아 스타일의 텍스트 중심 컴팩트 리스트 UI.
    *   상세 정보 확인 및 필터/검색 기능.
*   **관리자**:
    *   **정보 등록**: PDF 파일 업로드, 외부 URL 등록, 전용 이메일 발송.
    *   **추출 및 검토**: AI(OpenAI)를 통한 자동 정보 추출 및 `DRAFT` 상태 저장.
    *   **비교 대조**: 원본(PDF/텍스트)과 추출 결과를 1:1로 비교하며 수정할 수 있는 검토 화면.
    *   **승인 프로세스**: 관리자의 최종 승인 버튼 클릭 시에만 구직자에게 노출 (`PUBLISHED` 상태 변경).
    *   **관리**: 기존 공고의 수정 및 삭제.

### 3.2 비기능적 요구사항 (Non-functional)
*   **데이터 정확성**: 관리자 검토 단계를 거쳐 정보의 신뢰도 확보.
*   **사용성**: 관리자가 원본과 데이터를 대조하기 쉬운 UI 제공.
*   **보안**: 관리자 권한 제어 및 데이터 암호화.

## 4. 데이터 모델 (Data Model)

### JobPosting (채용 공고)
*   `id`: 고유 식별자
*   `companyName`: 회사명
*   `location`: 회사 위치
*   `position`: 채용 분야 (직무)
*   `requirements`: 채용 조건
*   `salary`: 예상 급여
*   `applicationPeriod`: 지원 기간
*   `applicationMethod`: 지원 방법
*   `status`: 상태 (`DRAFT`, `PUBLISHED`, `EXPIRED`)
*   `sourceType`: 출처 (`PDF`, `URL`, `EMAIL`)
*   `createdAt`, `updatedAt`: 생성 및 수정 일시

## 5. UI/UX 디자인 (UI Design)

### 5.1 구직자 목록 화면 (Saramin Style)
*   텍스트 가독성에 집중한 표(Table) 형태의 리스트.
*   한 행에 회사명, 직무, 급여, 마감일 등의 핵심 정보를 요약 표시.

### 5.2 관리자 검토 화면 (Comparison View)
*   **좌측 (Source)**: 업로드된 PDF 원본 또는 크롤링된 텍스트 표시.
*   **우측 (Editor)**: AI가 추출한 필드를 수정할 수 있는 폼.
*   **하단 (Actions)**: `승인 및 공개`, `임시 저장`, `삭제` 버튼.

## 6. 테스트 전략 (Testing Strategy)
*   **Unit Tests**: AI 추출 로직, 이메일 파싱 로직, 상태 변경 로직 검증.
*   **Integration Tests**: PDF 업로드부터 DRAFT 생성까지의 흐름 검증.
*   **E2E Tests**: 관리자 승인 후 구직자 목록에 정상 노출되는지 확인.
