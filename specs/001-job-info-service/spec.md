## User Scenarios & Testing *(mandatory)*

### User Story 1 - 채용 정보 조회 (구직자) (Priority: P1)

구직자는 웹 브라우저를 통해 현재 진행 중인 다양한 기업의 채용 정보를 한눈에 확인하고 상세 내용을 파악할 수 있습니다.

**Why this priority**: 서비스의 핵심 가치이며 가장 많은 사용자가 이용하는 기능입니다.

**Independent Test**: 구직자 권한으로 메인 페이지에 접속하여 등록된 채용 정보 목록이 정상적으로 표시되고, 상세 페이지로 이동하여 정확한 정보(회사명, 급여 등)가 보이는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 채용 정보가 시스템에 등록되어 있을 때, **When** 구직자가 메인 페이지에 접속하면, **Then** 채용 정보 목록(회사명, 분야 등)이 리스트 형태로 표시됩니다.
2. **Given** 채용 목록이 표시될 때, **When** 구직자가 특정 항목을 클릭하면, **Then** 해당 채용의 상세 정보(위치, 조건, 지원방법, 예상급여 등)가 표시됩니다.

---

### User Story 2 - 관리자 채용 정보 등록 (PDF 및 URL) (Priority: P2)

관리자는 PDF 파일을 업로드하거나 외부 URL을 등록하여 시스템이 자동으로 채용 정보를 추출하고 **즉시 구직자에게 공개**하도록 할 수 있습니다.

**Why this priority**: 데이터를 효율적으로 축적하고 신속하게 정보를 제공하기 위한 핵심 기능입니다.

**Independent Test**: 관리자 계정으로 로그인하여 PDF 파일을 업로드하거나 URL을 입력한 후, 시스템이 정보를 성공적으로 추출하여 별도의 승인 절차 없이 목록에 즉시 표시되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 관리자로 로그인했을 때, **When** 채용 정보 PDF 파일을 업로드하면, **Then** 시스템이 파일 내용을 분석하여 정보를 추출하고 성공 시 즉시 공개 상태로 등록합니다.
2. **Given** 관리자로 로그인했을 때, **When** 채용 공고 URL을 입력하면, **Then** 시스템이 해당 URL을 방문하여 정보를 추출하고 성공 시 즉시 공개 상태로 저장합니다.

---

### User Story 3 - 이메일을 통한 정보 등록 (Priority: P3)

관리자는 특정 제목 형식을 갖춘 이메일을 발송하여 시스템에 채용 정보를 자동으로 전달하고 **즉시 공개**할 수 있습니다.

**Why this priority**: 관리자의 등록 편의성과 정보 제공의 신속성을 극대화합니다.

**Independent Test**: "[연암취업정보]"로 시작하는 제목의 이메일에 채용 관련 URL을 포함하여 발송한 후, 시스템이 이를 수신하여 정보를 추출하고 즉시 구직자 목록에 노출하는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 관리자 권한 이메일 계정에서, **When** 제목이 "[연암취업정보]"로 시작하는 메일을 발송하면, **Then** 시스템이 메일을 수신하고 정보를 추출하여 성공 시 즉시 자동 공개합니다.
2. **Given** 이메일 제목이 조건을 만족하지 않을 때, **When** 메일을 발송하면, **Then** 시스템은 해당 메일을 무시하고 정보를 처리하지 않습니다.

---

### User Story 4 - 채용 정보 관리 (수정/삭제) (Priority: P2)

관리자는 이미 등록된 채용 정보에 오류가 있거나 기간이 만료된 경우 이를 직접 수정하거나 삭제할 수 있습니다.

**Why this priority**: 데이터의 최신성과 정확성을 유지하기 위해 필수적입니다.

**Independent Test**: 관리자 페이지에서 기존 정보를 수정하거나 삭제했을 때, 구직자 화면에 변경 사항이 실시간으로 반영되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 관리자 권한으로 정보 관리 페이지에 있을 때, **When** 특정 채용 정보를 수정하면, **Then** 변경된 내용이 즉시 저장되고 사용자 화면에 반영됩니다.
2. **Given** 관리자 권한으로 정보 관리 페이지에 있을 때, **When** 특정 채용 정보를 삭제하면, **Then** 해당 정보는 시스템에서 영구히 제거되거나 비활성화되어 구직자에게 보이지 않습니다.

### Edge Cases & Detailed Requirements

#### 1. 추출 소스별 예외 처리 (Edge Cases)
- **이미지 형태의 PDF**: 텍스트 추출이 불가능한 스캔된 이미지 PDF의 경우, OpenAI의 멀티모달(Vision) 기능을 활용하여 텍스트를 추출함. 만약 AI 분석으로도 핵심 정보(회사명, 직무) 추출이 불가능할 경우, 해당 건은 `ExtractionLog`에 실패로 기록하고 관리자에게 알림을 발송함. [Ref: CHK001]
- **URL 스크래핑 실패**: 대상 사이트의 구조 변경이나 접근 차단(403 Forbidden 등) 발생 시, 시스템은 최대 3회 재시도를 수행함. 최종 실패 시 관리자에게 'URL 분석 실패' 상태를 보고하고, 관리자가 직접 정보를 입력할 수 있는 빈 양식 페이지를 제공함. [Ref: CHK002, CHK012]
- **이메일 내 다중 URL**: 이메일 본문에 여러 개의 URL이 포함된 경우, 시스템은 채용 공고 형식을 갖춘 모든 유효한 URL을 개별적으로 방문하여 정보를 추출함. 단, 동일한 도메인의 반복적인 링크는 중복 제거 로직을 거침. [Ref: CHK003]
- **이메일 보안**: 등록되지 않은 관리자 이메일 주소로부터 발신된 "[연암취업정보]" 메일은 보안상의 이유로 무시하며, 로그에 '미등록 발신자 접근'으로 기록함. [Ref: CHK011]

#### 2. 데이터 정합성 및 중복 처리
- **필수 항목 누락 시 처리**: 추출된 정보 중 필수 항목(회사명, 위치, 채용분야)이 누락된 경우, 시스템은 해당 정보를 즉시 공개하지 않고 `JobPosting`의 `status`를 `PENDING`으로 저장함. 관리자 대시보드에 '검토 필요' 항목으로 표시하여 수동 보완을 유도함. [Ref: CHK004, CHK009]
- **중복 채용 정보 방지**: (회사명 + 채용분야 + 마감일)의 조합이 동일한 기존 데이터가 존재할 경우, 신규 등록을 차단하고 기존 데이터를 업데이트할지 여부를 관리자에게 묻거나 로그에 기록함. [Ref: CHK010]

#### 3. OpenAI 추출 엔진 상세 사양 [Ref: CHK015, CHK016, CHK017]
- **입력 제한**: PDF 파일은 최대 10MB, 50페이지 이내로 제한함. 이를 초과하는 경우 텍스트만 추출하여 토큰 제한 내에서 분할 처리(Chunking)를 수행함.
- **응답 검증**: AI 모델의 비결정적 특성(Hallucination 등)에 대비하여, 추출된 결과가 미리 정의된 JSON 스키마를 준수하는지 유효성 검사를 수행함. 스키마 위반 시 재요청을 1회 수행함.
- **성공 측정 지표 (SC-003 상세)**: 정보 추출 정확도 90%는 `(추출 성공한 필수 필드 수 / 전체 등록 시도 건의 필수 필드 총수) * 100`으로 계산하며, 정답 데이터셋(Golden Set)과 비교하여 측정함. [Ref: CHK007, SC-013]

#### 4. 로그 및 모니터링 [Ref: SC-014]
- **ExtractionLog 상세**: 추출 일시, 원본 소스(URL/파일명/이메일ID), 성공 여부, 사용된 AI 모델 버전, 소요 시간, 추출된 데이터 원본(Raw Data)을 기록하여 사후 검토 및 학습에 활용함.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 구직자에게 회사명, 위치, 채용분야, 조건, 지원기간, 방법, 예상급여 정보를 표시해야 함.
- **FR-002**: 관리자만 채용 정보를 생성, 수정, 삭제할 수 있는 권한 관리 기능을 제공해야 함.
- **FR-003**: PDF 파일 업로드 및 텍스트/데이터 추출 기능을 제공해야 함. (이미지 PDF의 경우 Vision 분석 포함)
- **FR-004**: 입력된 URL에 접근하여 웹 스크래핑을 통해 채용 정보를 자동 추출하는 기능을 제공해야 함.
- **FR-005**: 이메일 수신 및 제목 필터링("[연암취업정보]") 기능을 제공해야 함.
- **FR-006**: 추출 성공 시 시스템은 정보를 즉시 자동 공개 상태로 등록해야 함 (필수 항목 누락 시 PENDING).
- **FR-007**: 관리자가 이미 공개된 정보나 자동 추출된 로그를 검토하고 사후 수정/삭제할 수 있는 인터페이스를 제공해야 함.
- **FR-008**: 개발자 및 관리자가 API 명세를 확인하고 테스트할 수 있도록 Swagger UI 페이지를 제공해야 함.

### Security Requirements *(mandatory)*

- **SR-001**: 모든 관리자 로그인 및 개인정보(구직자 접속 기록 등) 전송 시 HTTPS 프로토콜을 필수적으로 사용함.
- **SR-002**: 관리자 계정의 비밀번호 및 민감한 시스템 설정 데이터는 암호화하여 저장함.
- **SR-003**: 이메일을 통한 정보 등록 시, 등록된 관리자의 이메일 주소에서 발송된 것인지 검증하는 절차를 수행함.
- **SR-004**: URL 추출 기능 사용 시 악성 스크립트 실행 방지를 위한 샌드박스 또는 보안 필터링을 적용함.

### Key Entities *(include if feature involves data)*

- **JobPosting (채용 공고)**: 회사명, 위치, 분야, 조건, 지원기간, 지원방법, 예상급여, 원본 출처(PDF/URL/Email)
- **Admin (관리자)**: 계정 정보, 권한 레벨, 등록된 발신 이메일 주소
- **ExtractionLog (추출 로그)**: 추출 일시, 출처, 성공 여부, 추출된 데이터 요약

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 구직자가 메인 페이지 접속 후 특정 채용 정보의 상세 내용을 확인하는 데까지 소요되는 단계가 2단계 이내여야 함.
- **SC-002**: 관리자가 URL 등록 시, 시스템이 정보를 추출하여 검토 화면에 표시하기까지의 시간이 10초 이내여야 함.
- **SC-003**: 유효한 텍스트 기반 PDF 파일 업로드 시 정보 추출 정확도가 90% 이상이어야 함 (필수 항목 추출 기준).
- **SC-004**: 권한이 없는 사용자가 수정/삭제 API에 접근할 때 100% 차단되어야 함.
- **SC-005**: 제목 규칙을 준수한 이메일 수신 후 5분 이내에 시스템에 등록 대기 상태로 반영되어야 함.

## API Endpoints

서비스에서 제공하는 주요 API 엔드포인트 요약입니다. (상세 명세는 `contracts/api-spec.md` 참조)

### 일반 사용자용
- **`GET /api/v1/jobs`**: 채용 정보 목록 조회 (페이징 지원)
- **`GET /api/v1/jobs/{id}`**: 채용 정보 상세 조회
- **`POST /api/v1/auth/register`**: 사용자 등록
- **`POST /api/v1/auth/login`**: 사용자 로그인
- **`POST /api/v1/auth/logout`**: 사용자 로그아웃
- **`POST /api/v1/healthcheck`**: 시스템 상태 확인

### 관리자 전용 (Admin 권한 필요)
- **`POST /api/v1/sources/pdf`**: PDF 업로드 및 정보 추출
- **`POST /api/v1/sources/url`**: URL 등록 및 정보 추출
- **`GET /api/v1/crawl?url={url}`**: 특정 URL의 원본 텍스트 크롤링 (데이터 확인용)
- **`POST /api/v1/jobs`**: 관리자 수동 채용 정보 생성
- **`PUT /api/v1/jobs/{id}`**: 채용 정보 수정 및 승인
- **`DELETE /api/v1/jobs/{id}`**: 채용 정보 삭제
